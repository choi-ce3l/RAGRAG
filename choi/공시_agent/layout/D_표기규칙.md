사용처: `A_QA_답변_화면.md` [2]·[5] 영역, 02 검색 에이전트, 05 답변 생성 에이전트.

## 1. 파이프라인 상태 기호

| 기호 | 상태 | 의미 |
|---|---|---|
| ⏳ | 대기 | 아직 시작 안 함 |
| 🔄 | 진행중 | 현재 실행 중 |
| ✅ | 완료 | 정상 종료 |
| ♻️ | 재시도 | 04 검증 피드백으로 재작업 중 (최대 2회) |
| ❌ | 실패 | 오류로 중단 |
| ⏭️ | 건너뜀 | 앞 단계 결과상 실행할 필요 없음 |

### 배치
기호를 **줄 맨 앞**에 두고 점선 리더(`......`)는 쓰지 않는다.
이모지가 터미널에서 2칸을 먹어 오른쪽 정렬이 흔들리기 때문이다.
재시도 횟수 등 보조 정보는 오른쪽에 공백으로 띄운다.

```
🔗 파이프라인
   ✅ [01] 온톨로지/개념 매핑
   ✅ [02] 검색(RAG)
   ♻️ [03] 계산/추론          재시도 {{n}}/2
   🔄 [04] 도메인 전문가 검증
   ⏳ [05] 답변 생성
```

### 다른 영역과의 관계
- [6] 검증 상태의 ✅(검증완료) / ⚠️(검증 미흡)와 같은 계열로 맞춘 것이다.
  단 의미는 다르다 — [2]의 ✅는 "그 단계가 돌았다", [6]의 ✅는 "결과가 타당하다".
- 평가 리포트 [3] 오류 단계 분포에서도 실패 단계 표시에 ❌를 재사용한다.

## 2. 근거 좌표 포맷

### 형태 — 3줄 1블록
```
   [{{n}}] {{corp_name}} · {{report_nm}}{{정정플래그}}
       {{section_path}}{{표좌표}}
       rcept {{rcept_no}} · {{chunk_id}}
```

### 예시
```
📎 근거
   [1] 삼성전자 · 분기보고서 (2023.03)
       II. 사업의 내용 > 2. 주요 제품 및 서비스   [표 t1]
       rcept 20230515002335 · periodic_20230515002335#9.0

   [2] 삼성전자 · 사업보고서 (2024.12)  ⚠️정정
       III. 재무에 관한 사항 > 3. 연결재무제표   [표 t4]
       rcept 20250311001234 · periodic_20250311001234#31.2
```

### 필드 매핑 (out/chunks.jsonl 실제 필드)
| 자리 | 원본 필드 | 비고 |
|---|---|---|
| 기업 | `corp_name` | |
| 문서 | `report_nm` | 예: `분기보고서 (2023.03)` |
| 섹션 경로 | `section_path` | 이미 ` > ` 로 계층 구분됨. 없으면 `(섹션 미상)` |
| 표 좌표 | `table_ids` | `block_type == "table"` 일 때만. `#9:t1` → `[표 t1]` |
| 접수번호 | `rcept_no` | |
| 청크 | `chunk_id` | 재현·디버깅용 |

### 플래그
| 플래그 | 조건 | 의미 |
|---|---|---|
| `⚠️정정` | `is_correction` | 정정공시 |
| `⛔대체됨` | `is_superseded` | 후속 공시로 대체된 문서 |
| `🚫제외` | 인젝션 감지 (상태 S4) | 근거에서 뺀 문서. 좌표만 남기고 사유 병기 |

> 전체 287,190청크 중 `is_correction` 17%, `is_superseded` 17%. 무시할 수 없는 비율이라
> 플래그를 좌표에 노출한다.

### 규칙
- 표가 여러 개면 `[표 t1, t4]` 로 나열한다.
- 답변 본문([3] 영역) 안에서는 **`[1]` 번호만** 쓴다. 전체 좌표는 [5] 영역에서만 편다.
- 근거 블록 사이는 빈 줄 하나로 띄운다.

### 변형 — XBRL fact 근거 (수치 fact-path)
근거가 청크가 아니라 XBRL fact인 경우 `section_path`가 없다. 같은 3줄 골격을 유지하되
2번째 줄만 재무제표 좌표로 바꾼다. 구현: `qa/pipeline.py`의 `to_coordinate()`.

```
   [1] 삼성전자 · 사업보고서 (2025.12)
       손익계산서(연결) > 매출액 (주30)   [셀 r1:c57]
       rcept 20260310002820 · periodic_20260310002820:IS_C2:r1:c57
```

| 자리 | 청크 근거 | XBRL fact 근거 |
|---|---|---|
| 2줄 경로 | `section_path` | `statement` 한글명 + `(scope)` + `label_raw` |
| 2줄 꼬리 | `[표 t1]` | `[셀 r{행}:c{열}]` |
| 3줄 식별자 | `chunk_id` | `fact_id` |

`statement` 한글 매핑: `balance_sheet`→재무상태표, `income_statement`→손익계산서,
`cashflow`→현금흐름표, `ratio`→재무비율.

> **셀 번호는 `fact_id`에서 뽑는다.** 레코드의 `col_index`는 매칭 순번이라
> `fact_id`의 컬럼 번호(=`fiscal_term`)와 다른 값이며, 그대로 쓰면 엉뚱한 셀을 가리킨다.

> `report_nm`은 factstore 레코드에 없어 `rcept_no`로 chunks.jsonl을 한 번 훑어
> 캐시한다(`qa/rcept.py`, 4,201건, 최초 5초). 캐시가 없으면 `doc_id`로 대체 표시된다.

## 3. 문항별 상세 테이블 컬럼 (평가 리포트 [5])

**좁은 표 + 오답 펼침** 구조. 표는 전체를 훑는 용도, 원인 파악은 아래 펼침 블록에서 한다.

### 컬럼 정의
| 컬럼 | 폭 | 원본 | 값 |
|---|---|---|---|
| `qid` | 6 | 데이터셋 `qid` | 재실행·재현 키 |
| `유형` | 8 | 데이터셋 `slice` | `compute` / `ratio` / `restate` / `narrative` … 넘치면 자름. 없으면 `➖` |
| `행동` | 6 | 기대 행동 × 파이프라인 상태 | ✅ 일치 / 🟡 해롭진 않으나 미흡 / ❌ 틀린 행동 |
| `정확` | 6 | 채점 결과 | ✅ `must_contain` 전부 충족 & `must_not_contain` 미포함 / ❌ |
| `근거` | 6 | `rcepts`(+`segments`) 대조 | ✅ 전부 일치 / 🟡 일부 / ❌ 불일치 / ➖ 정답 좌표 없음 |
| `오류단계` | 10 | 파이프라인 추적 | `[01]`~`[05]` / `-` (정답) |
| `검증` | 6 | 04 에이전트 결과 | ✅ 검증완료 / ⚠️ 검증 미흡 / ➖ |
| `소요(s)` | 8 | 실행 시간 | 타임아웃(E2) 추적용 |

### 이모지 폭 규칙 — 표가 깨지지 않게
`✅ ❌ ⚠️ 🟡 ➖` 는 터미널에서 모두 **2칸**을 차지한다.
따라서 `정확`·`근거`·`검증` 컬럼은 **셀당 반드시 이모지 1개만** 넣는다.
`-` 같은 1칸 문자를 섞으면 그 행부터 세로선이 어긋나므로 "없음"도 `➖`로 쓴다.
(`오류단계` 컬럼은 이모지가 없으므로 `-` 그대로 써도 된다.)
패딩은 글자 수가 아니라 **표시 폭**(East Asian Wide 반영)으로 계산한다.

### 펼침 블록
표 아래에 **정확 ❌ 또는 근거 ❌/🟡 또는 검증 ⚠️** 인 문항만 편다.

```
   ▼ 오답·실패 상세 ({{n}}건)

   [{{qid}}] {{question}}
        gold : {{gold_value 또는 must_contain}}
        pred : {{모델 답변에서 추출한 값}}
        근거 : rcept {{rcept_no}} {{아이콘}}
        단계 : [{{nn}}] {{단계명}} — {{사유}}
```

### 행동 축 — 내용 정확도와 독립된 두 번째 축
"무엇을 답했는가"와 "답했어야 했는가"는 다른 질문이다. 후자는 답의 자료형과 무관해
**전 문항에서 잰다** — 수치 비교가 안 되는 문항도 포함해서.

| 파이프라인 상태 | 행동 |
|---|---|
| `S0` | 답변 |
| `S2` | 답변+단서 |
| `S1` | 거절(없음) |
| `S3` | 되물음 |
| `S6` | 미지원 |

기대 행동은 데이터셋의 `expected_behavior`에서 온다. 없으면 `답변`으로 기본값
처리하되 **리포트에 그 사실을 표시한다** — 안 그러면 "답을 냈는가"를 행동 정확도로
오해하게 된다.

`전제지적`·`부분거절`은 ✅를 받을 수 없다. 전제를 지적하거나 일부만 거절하는 기능이
아예 없기 때문이다. **능력 공백은 지표에도 공백으로 남기는 편이 정확하다** —
비슷한 상태를 ✅로 쳐주면 없는 기능이 있는 것처럼 보인다.

### 컬럼이 요구하는 데이터셋 최소 스키마
기존 골드셋(`goldset_layerA/B/C`, `testset/labels.jsonl`)에 이미 다 있는 필드다.

| 필드 | 필수 | 채우는 컬럼 |
|---|---|---|
| `qid` | ✔ | qid |
| `question` | ✔ | 펼침 블록 |
| `must_contain` | ✔ | 정확 |
| `must_not_contain` | | 정확 |
| `slice` | | 유형 (없으면 ➖) |
| `rcepts` | | 근거 (없으면 ➖) |
| `segments` | | 근거 (섹션 단위까지 볼 때) |
| `gold_value` | | 펼침 블록 gold |
| `expected_behavior` | | 행동 (없으면 `답변`으로 기본값 + 경고) |

> `소요(s)`·`오류단계`·`검증`은 데이터셋이 아니라 **실행 결과**에서 나온다.

## 4. 시각화 (평가 리포트 [6])

**진단 3종, 터미널 ASCII 막대.** matplotlib 등 외부 의존성 없음.
같은 ASCII를 `data/eval_reports/report.md` 안에 코드블록으로 그대로 넣는다.
(한글 폰트 깨짐 문제가 없고, md에 붙여도 그대로 보이는 게 이 방식의 이유다.)

### 막대 문자
| 문자 | 용도 |
|---|---|
| `█` U+2588 | 채움 |
| `░` U+2591 | 빈칸 |

둘 다 1칸이라 폭 계산이 단순하다. 2절·3절의 이모지(2칸)와 섞는 칸에서는
3절의 폭 규칙을 그대로 따른다.

### ① 유형별 정확도
라벨 폭 8, 막대 **16칸 고정**(1칸 = 6.25%p). 오른쪽에 % 와 (맞음/전체).

```
   ① 유형별 정확도
      compute  ████████████░░░░  {{%}}  ({{n}}/{{n}})
      ratio    ███████░░░░░░░░░  {{%}}  ({{n}}/{{n}})
      restate  ██████████████░░  {{%}}  ({{n}}/{{n}})
```
데이터 출처: [5] 표의 `유형` × `정확` 집계.

### ② 오류 단계 분포
라벨 폭 10, 막대 **10칸**을 최댓값 기준으로 정규화. 오른쪽에 건수.

```
   ② 오류 단계 분포
      [01] 온톨로지  ██░░░░░░░░  {{n}}건
      [02] 검색      ████░░░░░░  {{n}}건
      [03] 계산/추론 ██████████  {{n}}건
      [04] 검증      ░░░░░░░░░░  {{n}}건
      [05] 답변생성  ██░░░░░░░░  {{n}}건
```
데이터 출처: [3] 영역과 같은 집계를 막대로 다시 보여주는 것.

### ③ 근거 × 정확 교차
검색이 문제인지 계산이 문제인지 가르는 2×2. 이 리포트에서 가장 진단적인 칸이다.

```
   ③ 근거 × 정확 교차
                정확 ✅    정확 ❌
      근거 ✅    {{n}}       {{n}}   ← 검색은 맞고 계산이 틀림 (03 문제)
      근거 ❌    {{n}}       {{n}}   ← 검색부터 틀림 (02 문제)
```

#### 네 칸 해석
| 칸 | 뜻 | 조치 |
|---|---|---|
| 근거 ✅ · 정확 ✅ | 정상 | — |
| 근거 ✅ · 정확 ❌ | 문서는 제대로 찾았는데 수치가 틀림 | **03 계산/추론** 손볼 것 |
| 근거 ❌ · 정확 ✅ | 엉뚱한 문서를 근거로 댔는데 답은 맞음 | **우연히 맞은 것.** 정확도에 포함시키되 신뢰하지 말 것 |
| 근거 ❌ · 정확 ❌ | 검색부터 실패 | **02 검색** 손볼 것 |

> 노트 30의 진단("파이프라인·검색은 되나 재무제표 표의 숫자가 틀린다")이 이 표에서는
> `근거 ✅ · 정확 ❌` 칸이 크게 뜨는 형태로 나타난다.

### ④ 기대 행동 × 실제 행동
대각선이 일치다. 답해야 할 때 답했고, 되물어야 할 때 되물었는가.

```
   ④ 기대 행동 × 실제 행동
                    답변       답변+단서  거절(없음) 되물음     미지원
      답변(100)     {{n}}      {{n}}      {{n}}      {{n}}      {{n}}
      되물음(13)    ·          ·          ·          {{n}}      ·
      거절(없음)(8) ·          ·          {{n}}      ·          ·
      전제지적(12)  {{n}}      {{n}}      {{n}}      {{n}}      ·
```
`전제지적`·`부분거절` 행에는 대각선 칸 자체가 없다 — 그 기능이 없어서다.

### 나중에 PNG가 필요해지면
matplotlib이 현재 미설치다. 발표·보고서용 이미지가 필요해지면 그때
설치(승인 필요) + `NanumGothic` 폰트 지정으로 같은 3종을 PNG로 추가한다.
지금 구조를 바꿀 필요는 없다.
